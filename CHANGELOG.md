# Changelog

All notable changes to SmolPaw are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). There have been no versioned releases yet; dates are when changes landed.

## [Unreleased]

### Added
- Fake SMTP and IMAP server for tests (`tests/fake_mail.py`, #64): local in-memory mail server on `127.0.0.1` only, using standard library modules (no external dependencies, `smtpd` replacement for Python 3.12+). SMTP handler supports HELO/EHLO, MAIL FROM, RCPT TO (550 on `reject@...`), DATA, RSET, QUIT, and plain/login AUTH with test/test credentials; accepted messages are recorded in memory. IMAP handler supports LOGIN, LIST, SELECT INBOX, SEARCH (ALL, UNSEEN, SEEN, FROM, TO, SUBJECT, BODY, TEXT; any other criterion, such as NOT, OR or SINCE, or a missing argument, is answered with BAD rather than ignored), FETCH (envelope, headers, body, flags, size, UID), STORE (+FLAGS, -FLAGS), APPEND to mailboxes (e.g. `Drafts`), and LOGOUT. Can be started from Python with dynamic port allocation (port 0) or run via CLI (`.venv/bin/python tests/fake_mail.py [smtp_port] [imap_port]`). Tests in `tests/test_fake_mail.py`.
- Non-interactive mode `agent.py -p "request"` with plain and JSON output (#67): runs one request and exits (no banner, no `You:` prompt, generic toolset only; `-p` with `--tools radarr` or `--web` is rejected with an error). In plain mode, prints the answer followed by the `[Harness says]` summary to stdout, including "no changes made" when nothing changed. `--json` streams the run's redacted log entries as JSON lines to stdout as they are written, ending with the `final` entry, routing the `[log]` path line and any errors to stderr. Approvals follow the read-only policy from scheduled runs (#52): every `[y/N]` confirmation is declined and reported in the harness summary, while `ask_user` receives `NO_ANSWER`. Exit codes reflect the outcome: 0 finished, 1 error (exception), 2 step limit reached, 3 stall stop. Tests in `tests/test_noninteractive.py`.
- Record the outcome of each scheduled run (#54): `schedules.json` now stores optional `last_status` and `last_error` fields per schedule. `last_status` is one of `running`, `ok`, `error`, `stopped`, or `needs_approval`. When a scheduled run starts, `schedules.mark_ran` sets `last_status` to `"running"` and clears `last_error`. In `web.py`, `Session._run` determines the outcome on completion (precedence: `stopped` > `error` > `needs_approval` > `ok`) and calls `schedules.mark_outcome`. To prevent leaking private data or secrets, `last_error` records only the exception class name and is empty for all non-error statuses; prompts, answers, messages, and tool output are never stored. Wrapped in error handling so a bad or missing `schedules.json` can never prevent the session from returning to `idle`. Schedules without these fields continue to load without file rewrites. Tests in `tests/test_schedules.py` and `tests/test_scheduler.py`.
- `tests/first_call_tokens.py`: measures the first model call's size in tokens on Ollama (whole call, instructions alone, and with `web_search` removed) in an isolated notes/skills setup. First figures, 2026-10-26: 4,407 tokens on Qwen 3.5 9B and 4,085 on Gemma 4 E4B, against the 2.2K to 2.9K the README, PLAN.md and RESULTS.md had been quoting; those now carry the measured figures, and PLAN.md notes that the 3.5K budget is already exceeded.
- Persistent deferred approvals across runs and restarts (#55, follow-up to #52 for step 3 of #20): `Session.needs_approval` holds a list of deferred action entries (`id`, `schedule_id`, `prompt`, `actions`, `t`), oldest first and at most one entry per schedule. On startup, `Session.__init__` scans up to 50 newest run logs in `g.LOG_DIR` and rebuilds the unhandled entries, redacting secrets with `g._redact`. Only a newer run that defers, or one that was dismissed, supersedes an older run of the same schedule, so the rebuild matches the live session (found in review: a newer clean or stopped run used to hide an older pending deferral after a restart). Added `Session.dismiss_approval(id: str) -> bool` to remove an entry and persist dismissal as a `<stem>.handled.txt` sidecar. Stopped runs no longer write a `deferred` entry to their run log so stopped runs never resurrect on rebuild. Tests in `tests/test_scheduler.py`.
- Scheduler thread and read-only mode for scheduled runs (#52, step 2 of #20): `scheduler.py` wakes every 30 seconds (started from `web.py`'s `main()`) and starts the due schedule with the oldest `next_run`, one per tick, only when no run is in progress and no prompt is pending; missed slots fire once, a corrupt `schedules.json` is reported once and does not stop the thread. A scheduled run is a normal run in its own thread with `schedule: <id>` in its log's `start` entry (new optional `schedule` argument to `run_request` and `generic_tools.start_log`). While it runs, `generic_tools.CONFIRM` declines at once and `ASK` returns `NO_ANSWER`; both are restored afterwards, including after an error or Stop. Declined actions go through the existing `DECLINED` path, are written to the log as a `deferred` entry and kept in `Session.needs_approval` (approving and re-running comes in step 3). The agent's prompt is unchanged. Tests in `tests/test_scheduler.py`, plus a test that interactive confirmations are unchanged.
- Cron parser and schedule store (`schedules.py`, #20): pure-Python 5-field cron expression parser (`minute hour day-of-month month day-of-week`) supporting steps, ranges, comma-separated lists, month and weekday names, strictly-after run calculations (`next_run`), and standard Vixie-cron day matching (DOM or DOW when both restricted). Atomic thread-safe schedule persistence in `schedules.json` (`load`, `add`, `remove`, `set_enabled`, `due`, `mark_ran`) ensuring missed slots fire once after sleep or restart and corrupt files raise without modification. Tests in `tests/test_schedules.py`.

### Fixed

- `web.py`: the conversation (including Activity) no longer shows on the Settings page on a wide screen.
- `web.py`: on a narrow window the Files and Settings panels no longer sit open above the conversation. They now come after it and collapse when the window is narrow.

### Added
- `web.py`: chats. Follow-up messages now continue the same chat instead of starting from nothing: the last three turns (answers clipped to 600 characters) are put before the new message for the model, and the run log keeps only your own message plus a `thread` id. Recents lists one entry per chat (with a message count); clicking one shows the whole chat and sending from it continues that chat, and New chat starts an empty one. Runs from before this change, and from the terminal agent, stay single-message entries. Adds a few hundred tokens to follow-ups only; first messages are unchanged. 8 new tests.

### Changed

A run that changed nothing no longer ends with "no changes made", live or when opened from Recents; the terminal keeps that line, and the log's `final` entry is unchanged. 2 new tests.
- PLAN.md: the first-call prompt budget is raised from about 3.5K to about 5K tokens, because the measured prompt was already 4.1K to 4.4K. Every addition is still measured with `tests/first_call_tokens.py` and `tests/eval.py`. The decision and its reasoning are in PLAN.md's Roadmap section.
- README: the intro and the closing comparison list the web page, folder listing and read-only scheduled runs, and the Tests section lists all three test files (CLAUDE.md likewise). Removed `eb.py`, an empty file committed by accident.
- `web.py`: Files now lives inside Settings as a read-only section (Notes, Skills and Memory, each collapsed), so the sidebar is just Chat and Settings. It also shows in eval mode, where the settings form is hidden.
- `web.py`: chat layout like other chat clients. The request box is pinned to the bottom of the page and clears when sent, the request shows as a bubble above the answer, Activity is a collapsible section under the answer instead of a right-hand column, and approval prompts appear just above the request box. The request box stays available while reading a past run; sending starts a new live run.

### Added
- `web.py`: pressing Enter in the request box or the `ask_user` answer box now sends it (Shift+Enter adds a newline), same as clicking Run or Send answer.
- The web page shows the output of the run's latest shell command or `list_dir` call in an Output card under the answer, so a listing is readable even when the model's answer does not repeat it.
- `tests/summary_cost.py` (#47) measures the cost of run summaries: seconds and tokens per summary, and the next request's wall time and steps with and without a summary in flight. Results in RESULTS.md.
- Model-written one-sentence summaries for Recent runs (#47): optional way for the loaded model to write a one-sentence summary of a finished run (at most 100 characters), stored in a sidecar `<log stem>.summary.txt` in `logs/` and shown in place of the prompt title, falling back to the title when absent. On by default; switch off with the Settings toggle or `SMOLPAW_RUN_SUMMARIES=0`. Generated lazily in a background thread after the answer is shown without blocking requests; skipped or cancelled if a new run starts while a summary is in flight. Redacted with `_redact` and `redact_pasted_secrets`. It adds one short extra model call per run (thinking off, output capped at 80 tokens; measured at about a second, see RESULTS.md). 19 new tests.
- `tests/skill_reuse.py` (#4, rung 5): on the Tidepool `detail` variant with an isolated empty skills folder, a discovery run, checks on the skill it wrote (written, no secrets, no copy of the answer, names the API path), then the same task again with the skill available. `--ask-for-skill` adds a sentence to the discovery prompt asking for one. Results in RESULTS.md.
- `list_dir(path)` tool (#46): exact names, sizes, subfolder item counts and a true entry count, formatted by the harness instead of transcribed by the model from `ls -la`. Same scoping as `read_file` (free in `workspace/` and `skills/`, asks elsewhere, `.ssh` blocked), capped at 200 listed entries with the true count kept, logged and shown in the web feed. Schema costs about 108 to 110 prompt tokens. `tests/eval.py --listing` (isolated 55-entry fixture) and `--without-tool` measure it; see RESULTS.md. 10 new tests.
- Recent runs now show a title above each run's summary line: the first sentence of the run's prompt, secret-redacted and clipped to 80 characters. It is a cheap stand-in for a real summary; model-written summaries are tracked in #47. 3 new tests.

### Security
- `ask_user` answers are now checked for a pasted credential (GitHub/AWS/OpenAI/Slack token shapes, JWTs, a conservative generic long-opaque-token catch-all) and redacted before reaching the model's context, the run log, or anything it echoes back. Found from a real session: a model asked a user directly for a GitHub token (against an instruction already telling it not to), the user pasted a real one, and it went completely unredacted into the log and the model's final answer. `_redact()` only ever covered pre-registered secrets from `notes.md`/`.env`; this is the backstop for anything pasted ad hoc. `GUIDANCE` now also says plainly never to ask for a credential, even if offered — the redaction is the real fix, the instruction alone had already failed once. 6 new tests. Closes #32.

### Fixed
- `run_shell` runs approved commands with `pipefail` (bash when available), so a failing first stage of a pipe no longer shows `exit 0` (#49).
- `tests/eval.py --listing` built no fixture when `--expect` was given, so a custom `--prompt` ran against a missing `downloads/` folder; it now always builds it.
- The 3-searches-per-request cap (#24) is now thread-safe: the check and increment share a lock, so parallel `web_search` calls cannot slip past it. The cap now resets in `start_log()` instead of through a `list` subclass that hooked `ACTIONS.clear()`; `ACTIONS` is a plain list again. 3 new tests, including 10 parallel searches letting exactly 3 through.
- `SMOLPAW_SEARCH_PROVIDER` in `.env` had no effect (#24): the provider was applied when `generic_tools.py` was imported, before `agent.py` and `web.py` load `.env`, so `none` did not remove `web_search` and a mistyped value was not caught at startup. `build_agent()` now applies it after `.env` is loaded. 1 new test, which imports first and sets the variable afterwards.
- `~` in shell paths: `_resolve` did not expand it, so `ls ~/Downloads` was judged a workspace path (`workspace/~/Downloads`), ran immediately without a shell, and failed with exit 1. `~` now expands for the scope check, so a home-folder path outside `workspace/` asks first like any other, and an in-scope path given with `~` is expanded before the command runs. Found in an exploratory run asking for the Downloads folder's contents. 3 new tests.
- Web page (#43): opening an old run no longer keeps the feed pinned after a new run starts, and the Recent runs list is re-read only when the run, its status or its summary changes, not every 1.5 seconds.
- The test suite wrote a stub run log to the real `logs/` on every run (one file per run, model `m`), which now crowded the web page's Recent runs list; those tests use a temp log directory.
- `run_shell` on Windows: the read-only allow-list (`ls`, `cat`, etc.) execed a bare binary with no shell, crashing with `FileNotFoundError: [WinError 2]` since there is no `ls.exe` on PATH by default; the confirm-required path used `shell=True`, which on Windows means `cmd.exe`, and `cmd.exe` does not understand `ls`/`cat` either (PowerShell aliases, not `cmd.exe` built-ins). Both paths now route through PowerShell on Windows, which knows `ls`/`cat` natively. `run_shell` also now catches `OSError` generally (not just `TimeoutExpired`) and returns a clean `ERROR:` instead of letting an unrunnable command crash the tool call. Found from a real session: this left a model with no working discovery tool partway through a task, which it tried to route around by asking the user for a credential directly (see Security, above). 3 new tests. Closes #33.

### Added
- The prompt now states the home folder and that shell commands start in `workspace/` (one line, built at run time). In the same exploratory run the model did not know the home folder, guessed `~`, then searched from `/` (a `find /` that timed out after 60s) and needed 5 approvals. Cost: 18 prompt tokens on Qwen 3.5 9B (Ollama `/api/generate`, `raw: true`, 2 identical readings, ad hoc with the `prompt_tokens` helper from `tests/tool_schema_tokens.py`). Not yet measured: whether the line stops the wandering; that needs a rerun of the same request.
- The run log's `shell` entries now include the first 500 characters of the command's output (redacted), so a run can be checked against what the model actually saw. Previously only the command and exit code were kept.
- `web_search(query)` tool (#24): pluggable web search returning up to 5 results with title, URL, and snippet. Enabled by default with no configuration beyond `./setup.sh` via the new `ddgs` dependency (DuckDuckGo search scraper). Includes pluggable provider architecture with SearXNG support via `SMOLPAW_SEARCH_PROVIDER=searxng` and `SMOLPAW_SEARCH_URL`, or `SMOLPAW_SEARCH_PROVIDER=none` to unregister the tool and save prompt tokens. Includes a per-request cap of 3 searches (reset automatically on each request), rate limit and timeout handling advising the model not to repeat failed queries, secret redaction, and logging to `web.py` and `export_findings.py`. Snippets are clipped to 300 characters. An invalid `SMOLPAW_SEARCH_PROVIDER` prints a warning and falls back to `ddgs` instead of crashing at import. The tool schema costs 91 tokens on Qwen 3.5 9B and 92 on Gemma 4 E4B (`tests/tool_schema_tokens.py`, Ollama `/api/generate` with `raw: true`, one run each; the first-call prompt total was not re-measured). 19 new tests plus more for the fallback and per-request reset. Fixes #24.
- Web UI settings card (#37): choose backend, model (suggestions from the server's `/v1/models`), step limit and prompt timeout from the page without restarting `web.py`. POST `/api/settings` validates the values and rebuilds the agent only between requests (409 while one runs); GET `/api/models?backend=` lists the server's model ids. Not included: loading or unloading models, showing the loaded context, and the Radarr toolset (web.py stays generic-only). 10 new tests.
- Token totals per run (#39): the run log's `final` entry records the run's input and output tokens, and the web page's run summaries show them (older logs and runs that did not finish show none).
- Web UI recent runs and run summary (#39): a "Recent runs" card on the web page listing up to 20 past runs from `logs/*.jsonl` (newest first) with a one-line summary (start time, model, duration or unfinished status, and tool-call count). Clicking a run displays its activity feed lines, with a "Back to live run" button to return to the current run. Authenticated GET `/api/runs` and GET `/api/run_feed?id=<id>` (read-only, with strict directory-listing id validation, returning 404 on path traversal or unknown ids). The current run's summary is included in `/api/state` and shown on the Activity card. All text inserted via `textContent` only, with redaction. 18 new tests. Fixes #39.
- Web UI read-only files view (#38): a collapsible Files card on the web page and authenticated GET `/api/files` returning JSON with secret-redacted, clipped contents of `notes.md`, `skills/*.md`, and `memory.md`. Only the three fixed sources are read; requests cannot supply paths. Inserted into the DOM using `textContent` only. 7 new tests. Closes #38.
- File and skill tools (`read_file`, `write_file`, `list_skills`, `read_skill`, `write_skill`) now log each call to the run log with outcome and metadata (path, chars, hit count, blocked/declined/error status), covering blocked secrets files and declined confirmations without logging file or skill contents. Both `web.py`'s activity feed and `tests/export_findings.py` render the new entry kinds. 18 new tests. Logging half of #39.
- Prompt-prefix caching measured on LM Studio and Ollama (#29): `tests/prefix_cache.py` (controlled cold, warm and changed-start calls, an append-only series, and the real Tidepool agent with per-step times) and a RESULTS.md section. A stable prompt start costs 0.2 to 1.7s to re-read against 4.5 to 57s cold; a changed first line costs the full read. LM Studio reuses the prefix from the second call, Ollama from the third. SmolPaw's prompt needs no reordering. `tests/eval.py` runs now record `step_stats` (seconds and tokens per model call). Corrected the earlier "not measured" caveats in RESULTS.md and README.md. 1 new test, which keeps `build_instructions()` free of anything that changes between calls. Closes #29.
- Pre-flight rejections from `http_request` (#31) are now logged as a `preflight` entry (method, URL, reason) and shown by `web.py`'s feed and `tests/export_findings.py`, so a run's rejections can be counted. They were previously visible only as the model's tool output. The two checks now live in one helper, `_preflight_problem`. 4 new tests. Closes #36.
- Pre-flight validation on `http_request` writes and required search queries (#31): catches obviously wrong requests before approval prompts or network calls occur. Queries with an empty value for a plainly required search parameter (`term=`, `query=`, `q=`) return an `ERROR:` telling the model which parameter is empty and to fill it in (observed on GET `/api/v3/movie/lookup` returning 503). Non-GET write requests (`POST`, `PUT`, `PATCH`) with empty or whitespace-only bodies return an `ERROR:` directing the model to look up the endpoint's schema first via the `api-discovery` skill / `openapi_search` (observed on `POST /api/v3/movie` with no body returning 415), while leaving `DELETE` and action-trigger POSTs (e.g. `/restart`, `/trigger`) unaffected. All returned error strings pass through `_redact`. `/command` is deliberately not exempt: Radarr and Sonarr's `POST /api/v3/command` needs a JSON body. Unmeasured against real models/services (eval against Rung 3 left for manual measurement). 12 new tests. Closes #31.
- `remember(fact)` and `recall(query)`: on-demand long-term memory tools. `remember` appends user preferences or lessons to `memory.md` upon explicit `[y/N]` approval, applying secret and credential redaction beforehand; `recall` searches `memory.md` (case-insensitive keyword/phrase matching) and runs freely without asking. Stored facts are never inlined into the prompt, avoiding the token creep of OpenClaw-style memory. The combined tool schema measures 179 tokens on Qwen 3.5 9B and 182 on Gemma 4 E4B (Ollama `/api/generate`, raw prompt, no chat template) — over the issue's 100 to 150 token budget; the original "~147 tokens" figure was derived from a hand-reconstructed partial schema, about a third smaller than the real one smolagents sends. Kept as-is for now since the overrun is modest against the project's ~3.5K first-call budget; worth trimming the docstrings if more tools push the total further. 20 new tests. Closes #27.
- Key user facts in `notes.md`: user preferences that shape answers (timezone, units, ownership) documented in `notes.example.md` and `README.md`, inlined into every call via `build_instructions()` instead of OpenClaw-style persona files. The example 3-line block measures 27 tokens against Qwen 3.5 9B's own tokenizer (Ollama `/api/generate`, raw prompt, no chat template), against an issue budget of 30 to 80 tokens; the original "~25 tokens" figure was an unmeasured guess that happened to land close. `services()` updated to strictly match `http(s)` URLs so user facts lines are never mistaken for network services. Closes #25.
- `fetch_page(url, query)`: on-demand web page tool returning readable text trimmed to sections matching a query, with surrounding line context, ellipses between non-contiguous blocks, page title preservation, and a clear preview message on no-match. Designed as a cheap, prompt-efficient stand-in for browser automation (its tool schema is 556 characters of JSON, a rough 120 to 150 tokens, not yet measured through a model's own tokenizer) so large pages do not flood model context. Runs freely without `[y/N]` confirmation (read-only GET), applies secret redaction, logs queries and hit counts to `web.py` and `export_findings.py`, and gives the same wrong-API-path warning as `http_request` instead of silently trimming a service's HTML. 15 new tests. Closes #28.
- Measured Rung 4 (unrelated local file task, #3): 6 of 6 passes across Qwen 3.5 9B and Gemma 4 E4B on Ollama (3/3 each, 19 to 51s, 4 to 10 steps). Both models consistently stuck to read-only shell commands and `read_file`, handled the write confirmation boundary without incident, and made zero phantom API/HTTP requests, confirming harness generality. Closes #3.
- Write verification, the second half of #19: after a `POST`/`PUT`/`PATCH`/`DELETE` that returns 2xx, `http_request` does a follow-up GET (free, no new approval) to check what actually happened, not just the status code — a POST against its `Location` header or an `id` in the response, a PUT/PATCH's submitted fields against what a GET now returns, a DELETE as actually gone (404). Mismatches and a still-present "deleted" resource are flagged with a loud `WARNING` in `[Harness says]`. Human-facing only (never reaches the model), so no prompt cost. 9 new tests. Closes #19.
- `agent.py --web`: prints a URL alongside the normal terminal session; `[y/N]` and `ask_user` prompts can then be answered either in the terminal or on that page, whichever comes first (`--web-host`/`--web-port` to match). Reuses `web.py`'s `Approvals` class unchanged; a new `terminal_relay()` makes the terminal a second client of it, the same way the browser already is. Only touches stdin while a prompt is actually pending, so it never competes with the normal "You:" input loop. 4 new tests, including that a stale terminal answer arriving just after the web page already answered does not flip the result.
- [TESTING.md](TESTING.md): a guide for exploratory testing on a second machine (setup with no services needed, a list of generic agentic tasks to try, how to send findings back), and `tests/export_findings.py`, which bundles every run log in `logs/` into one readable Markdown report for exactly that. Tests cover rendering, an unfinished run, a log with no start entry, and the combined report.
- `openapi_search` calls are now logged (spec URL, keyword, hit count or error), matching `http_request` and `run_shell`; `web.py`'s activity feed shows them too. Found as a real gap during rung 3 testing, where a model's "could not find it" claims could not be checked against the log (#30).
- `web.py`: a small rotating "Pawing... (12s)"-style line while a request is running, so the page shows it is still working and how long it has taken (standard library only, ticks client-side off the run's start time, no extra polling).
- `web.py`: a Copy button on the Answer card, using the Clipboard API where the page is a secure context, with a `document.execCommand` fallback for plain-HTTP access over Tailscale.
- Stall detection, the first half of #19 (recovery checks still open: verifying the outcome of a write): a `step_callbacks` hook in `agent.py` stops a run early if the model makes the same tool call with the same arguments three times running and every attempt fails (`ERROR:`/`DECLINED:`, an HTTP 4xx/5xx response, or a smolagents-level parsing/execution error). Reported the same way as the step cap: `STOPPED EARLY: ...` plus the last tool result. No prompt cost (pure bookkeeping over `agent.memory.steps`); a genuine interrupt from the web harness's Stop button is unaffected. Tests cover the matching logic and `run_request`'s handling of both cases.
- `http_request` converts web pages to plain text (title and visible text, `<main>` only when present, no scripts, menus or footers), standard library only. HTML from a service listed in `notes.md` still gets the wrong-path warning. Requests send a `SmolPaw` user agent. Tests cover conversion, the service warning and redaction ([#23](https://github.com/aurora7795/smolpaw/issues/23)).
- `web.py`: a web harness that runs the agent and puts its `[y/N]` prompts and `ask_user` questions on a phone-friendly page, with an access token, key redaction, an optional timeout (unanswered counts as no) and a Stop button. Standard library only. `tests/eval.py --confirm web` uses the same page. Tests cover tokens, stale and non-boolean answers, timeouts, redaction and the harness's decline record.
- Ollama as a second model backend: `agent.py --backend ollama` (port 11434, default model `qwen3.5:9b`). `build_agent()` takes a `backend` argument; LM Studio stays the default. Tests cover the backend selection ([#13](https://github.com/aurora7795/smolpaw/issues/13)).
- `--backend` for `tests/eval.py` and `tests/prefill_timing.py`. On Ollama they load the model, read its context from `/api/ps` and warn if it differs from `--ctx` ([#13](https://github.com/aurora7795/smolpaw/issues/13)).
- README section comparing SmolPaw with OpenClaw on prompt size, task time and local reading speed, with the limits of what was measured.
- `tests/eval.py`: runs a prompt N times on a model and records pass/fail, steps, time, tokens, tools and answer, with scripted confirmations and its own notes (the real `notes.md` is untouched). Can serve Tidepool itself (`--tidepool`).
- Tidepool variants `hint`, `detail` and `paged` in `tests/fake_api.py` for harder discovery tests.
